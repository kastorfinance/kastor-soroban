# Migration from BSC (Solidity) to Soroban

Source: `kastorfinance/kastor-smart-contracts` (Solidity 0.8, Brownie, 2022–2024). Per its `deployments_project_id_1/map.json`, the contracts deployed on BSC mainnet (chain 56) were `WhitelistVault`, `KastorToken` and `KastorEscrowV1`. `KastorEscrowMultiple` and `KastorRoyalties` exist in the source but do not appear in the deployment records.

## Contract mapping

| Solidity | Soroban | Notes |
|---|---|---|
| `WhitelistVault` | `kyc-registry` | Adds an expiry ledger per wallet. Drops `freewayMode`. Operators can also revoke. |
| `KastorToken` (ERC-1155, every property in one contract) | `property-token` (SEP-41, one instance per property) | `mint` once, restricted mode, transfer agents and lockable URI are kept. Adds a sender check and a verified recipient on mint. |
| `KastorEscrowMultiple`, `KastorEscrowV2`, `KastorEscrowV1` | `primary-sale` | Holding period, settle and refund are kept. Reserves units at purchase. Adds a buyer self-refund. Fixed USDC price, no oracle. |
| `KastorRoyalties` | `dividends` | Prefunded allocations and a one-time claim. Adds on-chain pro-rata. |
| `Transfers` (batch transfers from a source wallet) | *(not ported)* | Covered by `primary-sale` settlement and by `property-token.force_transfer` for agents. |
| `erc20_kas` (KAS utility token) | *(not ported)* | Out of scope: this port covers the investment flow only. |
| `AggregatorV3Interface` (Chainlink BUSD/USD) | *(removed)* | Payment is in USDC, so no conversion is needed. |

## Bugs found in the Solidity contracts

Found by reading the source. None of the three is in a contract listed in the mainnet deployment records, so no mainnet funds were exposed through them. Each has a test here that would fail with the Solidity logic.

| # | Contract / function | Problem | Impact | Fix and test |
|---|---|---|---|---|
| 1 | `KastorRoyalties.claim()` | Pays `_balances[msg.sender]` but never sets it to zero. | A holder can call `claim()` repeatedly and drain the source wallet, up to its allowance to the contract. | The balance is removed before paying. `dividends::test::claim_pays_once` |
| 2 | `KastorEscrowMultiple.completePurchase()` | Transfers the NFTs to `_msgSender()` (the operator calling the function), not to `userAddress`. | Settled units go to the operator's wallet. The buyer never receives them unless someone transfers them manually. (The same function also calls `safeTransferFrom(address(this), …)` on BUSD, which needs the contract to have approved itself, so as written it would revert first.) | Units go to the buyer. `primary_sale::test::complete_after_holding_delivers_to_buyer_not_operator` |
| 3 | `KastorEscrowMultiple.reversePurchase()` | Refunds `busdAmount` but does not `delete _userPurchases[...]`. | The same purchase can be refunded several times, and it can still be completed after being refunded. | The purchase is read and removed in one step (`take_purchase`) before paying. `primary_sale::test::purchase_cannot_be_settled_twice` |

There are also three weaker points in the Solidity design, changed here:

- **`buyTokens` in `KastorEscrowMultiple` does not reserve supply.** Supply is only reduced at `completePurchase`, so while purchases wait in escrow more units can be sold than exist. `primary-sale` reserves at `buy` (`cannot_oversell_reserved_units`).
- **`freewayMode` in `WhitelistVault`.** One call disables KYC for every property at once. Removed.
- **`KastorToken.safeTransferFrom` checks only the recipient.** A holder whose KYC was revoked can still send tokens out. `property-token` checks both sides (`revoked_holder_is_frozen`).

## Concepts that change between EVM and Soroban

| EVM | Soroban |
|---|---|
| `msg.sender` plus `require(hasRole(...))` | `address.require_auth()`: the signature is checked by the host, and the address is an explicit argument |
| `approve` + `transferFrom` for a contract to pull tokens | The buyer signs the `buy` invocation, and that authorization covers the nested `usdc.transfer` |
| Low-level `functionCall` with a selector | Typed client generated by `#[contractclient]` |
| Storage lives forever | Entries have a TTL that is extended on use; allowances are temporary entries |
| `block.timestamp` | `env.ledger().sequence()` (about 5 s per ledger) |
| `revert("string")` | `#[contracterror]` codes, visible in the explorer as `Error(Contract, #n)` |
